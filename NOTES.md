## Tool wrappers (4-file convention + `_normalize.py`)

### Shared LocalRunner mechanics (apply to every GPU tool)
- **Container UID/GID:** `docker run -u $(id -u):$(id -g)` so workspace artifacts aren't root-owned. Tool Dockerfiles must NOT set a restrictive `USER` (would block reading the bind-mounted entrypoint).
- **Weight caches mount at `/cache/<name>`** (not `/root/.cache`, which UID 1000 can't write). Each tool's Dockerfile sets its env (`HF_HOME=/cache/huggingface`, etc.) + `mkdir -p /cache/<name>`.
- **Build context staging:** `_ensure_image` copies the tool dir + `_SHARED_BUILD_FILES` (`_gpu_metrics.py`) into a tempdir so Dockerfiles can `COPY _gpu_metrics.py` (no path-traversal in build context). Add new shared helpers there.
- **Path translation:** `_translate_workspace_paths` rewrites `/workspace/...` in result envelopes → host paths. Containers tagged `--label proteinclaw.session=<sid>` (used by `proteinclaw cancel`).
- **`_normalize.py` per tool** (the allowed 5th file): parameter/PDB normalisation extracted so host-side tests import it without container-only imports. Tests MUST load it via `importlib.util.spec_from_file_location` under a **unique** module name — plain `from _normalize import` collides across tools in one pytest session.

### Conditional JSON-Schema (`allOf`/`if`/`then`/`else`) in a tool.yaml silently DROPS the tool from the agent (2026-06-07)
**Symptom:** run `b269b01802e5` made **0 RFD3 calls** and the agent's plan.md said *"RFdiffusion3 … was not loaded in this session's deferred-tools list"* — it reused prior backbones instead. The immediately-prior run `a89c4dfe5a89` (before the edit) called RFD3 fine. **Root cause:** I had added an `allOf: [{if/then/else}]` block to RFD3's `tool.yaml` to make `required` conditional (de-novo vs partial mode). The registry's `Draft202012Validator.check_schema` *accepts* it, and `build_mcp_server` builds fine — but the agent runs under the **`claude_code` system-prompt preset** (`core._build_options`), which uses **deferred tools / ToolSearch** and sends each tool's schema as an **Anthropic tool `input_schema`**. The API tool-schema validator does **NOT** support `allOf`/`if`/`then`/`else`/`oneOf`/`anyOf` — so RFD3's schema was rejected and the tool silently vanished from the agent's loadable set (every other tool has a flat schema and survived). **Fix:** reverted RFD3 to a flat schema (no `required`, no `allOf`); the two modes are enforced at runtime by `normalize_args`/`normalize_partial_args`, NOT jsonschema (runtime args are never jsonschema-validated — confirmed: `router.route`→`runner.run` does no schema validation). **Rule: keep every `tool.yaml` `parameters` schema FLAT** — type/properties/required/enum/min/max/pattern only; no conditional keywords, or the tool disappears from the agent under the claude_code preset. tool.yaml is host-read by the registry (NOT baked into the image) so schema fixes need no rebuild.
